# Plan: Rust CLI to Upload Files to Cloudflare R2

## 1. Goal & Assumptions

**Goal:** Build a minimal, ergonomic Rust CLI (`cloudflare_r2`) that uploads a local file to a Cloudflare R2 bucket via the S3-compatible API using an `upload` subcommand.

**User decisions:**
- (2026-05-13) `Simple upload-only` — file arg + `--key`, credentials from env vars / flags. No config file, no download/list scope for v1.
- (follow-up) **`use upload subcommand`** — CLI must be `cloudflare_r2 upload <FILE> [options]` (not flat `cloudflare_r2 <FILE>`). Extensible for future `list`/`get`/`delete` subcommands.

**Assumptions (to validate; all changeable without re-planning):**
- Single-file upload only (no recursive directory upload). If user passes a directory, error with hint.
- If `--key` omitted, use filename (basename) as object key.
- S3-compatible auth via R2 API tokens: `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET` (+ optional `R2_ENDPOINT`). CLI flags override env vars.
- Endpoint derived as `https://{account_id}.r2.cloudflarestorage.com` unless `--endpoint` explicitly given.
- Runtime: `tokio` async, `aws-sdk-s3` (Cloudflare’s recommended Rust path), streaming via `ByteStream::from_path`.
- Content-Type auto-detected via `mime_guess`; override with `--content-type`.
- No progress bar in v1 (keeps deps small); add `indicatif` later if needed.

**Out of scope v1:** multipart manual tuning, directory recursion, download/list, presigned URLs, wrangler integration.

**Repo state: Greenfield**
- `Cargo.toml` — `name = "cloudflare_r2"`, `version = "0.1.0"`, `edition = "2024"`, **zero dependencies**. `src/main.rs` only `println!("Hello, world!")`. Entire implementation is new.

- No existing `.agents/plans`, no config, no tests, no CI. Durable paths: `Cargo.toml`, `src/main.rs`.

**Cloudflare canonical Rust pattern (https://developers.cloudflare.com/r2/examples/aws/aws-sdk-rust/):**
```rust
let config = aws_config::from_env()
    .endpoint_url(format!("https://{}.r2.cloudflarestorage.com", account_id))
    .credentials_provider(aws_sdk_s3::config::Credentials::new(access_key_id, access_key_secret, None, None, "R2"))
    .region("auto")
    .load().await;
let client = s3::Client::new(&config);
// upload:
let body = ByteStream::from_path(Path::new(file_path)).await.unwrap();
client.put_object().bucket(bucket).key(key).body(body).send().await?;
```
Pattern must be mirrored. Region `"auto"` required but ignored by R2. `ByteStream::from_path` is retryable TOKIO-backed stream.

**CLI idioms:** `clap` derive API with typed `PathBuf`, subcommands via `#[derive(Subcommand)]`, `anyhow` for error context, `mime_guess` for content-type, `tokio` required for `ByteStream::from_path`.

## 3. Proposed Implementation

### 3.1 Dependencies (`Cargo.toml`)
```toml

aws-sdk-s3 = "1"

# optional but recommended:

```

Pin `aws-sdk-s3 = "1.x"` + `aws-config = "1.x"` — both at 1.x track; verify `cargo add` resolves compatible `aws-smithy-*`.

*Rejected:* `s3` crate (rust-s3) — less Cloudflare-documented; `reqwest` manual SIGv4 — unnecessary when `aws-sdk-s3` handles signing.

### 3.2 CLI Design (`src/main.rs` → split later into `src/cli.rs` + `src/r2.rs` if >200 LOC)

**Binary name:** `cloudflare_r2` → `cargo run -- upload ...` / `cargo install` produces `cloudflare_r2`. Future alias `r2` possible via `[[bin]]`.

**Required `clap` structure with `upload` subcommand:**
```rust
use clap::{Parser, Subcommand};
use std::path::PathBuf;

#[derive(Parser)]
#[command(name="cloudflare-r2", version, about="Upload files to Cloudflare R2", arg_required_else_help=true)]
struct Cli {
    #[command(subcommand)]
    command: Commands,

    /// Verbose logging (global)
    #[arg(short, long, global=true)]
    verbose: bool,
}

#[derive(Subcommand)]
enum Commands {
    /// Upload a file to R2
    Upload(UploadArgs),
}

#[derive(Parser)]
struct UploadArgs {
    /// Local file to upload
    #[arg(value_name="FILE")]
    file: PathBuf,

    /// Object key in bucket (defaults to filename)
    #[arg(short, long)]
    key: Option<String>,

    /// R2 bucket name (or env R2_BUCKET)
    #[arg(short, long, env="R2_BUCKET")]
    bucket: String,

    /// Cloudflare Account ID (or env R2_ACCOUNT_ID)
    #[arg(long, env="R2_ACCOUNT_ID")]
    account_id: Option<String>,

    /// Full R2 endpoint URL (or env R2_ENDPOINT); if omitted, https://{account_id}.r2.cloudflarestorage.com
    #[arg(long, env="R2_ENDPOINT")]
    endpoint: Option<String>,

    /// Access Key ID (or env R2_ACCESS_KEY_ID)
    #[arg(long, env="R2_ACCESS_KEY_ID", hide_env_values=true)]
    access_key: String,

    /// Secret Access Key (or env R2_SECRET_ACCESS_KEY)
    #[arg(long, env="R2_SECRET_ACCESS_KEY", hide_env_values=true)]
    secret_key: String,

    /// Content-Type override (auto-detected if absent)
    #[arg(long)]
    content_type: Option<String>,
}
```

**Invocation:**
```bash
cloudflare_r2 upload ./photo.jpg --bucket my-bucket --key images/photo.jpg
cloudflare_r2 upload ./README.md --bucket $R2_BUCKET  # key defaults to README.md
cloudflare_r2 upload --help
cloudflare_r2 --help  # shows subcommands
```

**Validation:**
- Check `file.exists() && file.is_file()` else `anyhow::bail!("not a file: {}", file.display())`.
- If `key` is None, `file.file_name()` → string.
- Require `endpoint` OR `account_id`; error message explains `R2_ACCOUNT_ID` or `--endpoint`.

### 3.3 R2 Client Factory (`src/r2.rs` or inline)

```rust
async fn build_client(account_id: Option<&str>, endpoint: Option<&str>, access_key: &str, secret_key: &str) -> s3::Client {
    let endpoint_url = endpoint.map(|s| s.to_string())
        .or_else(|| account_id.map(|id| format!("https://{id}.r2.cloudflarestorage.com")))
        .expect("account_id or endpoint required");
    let creds = aws_sdk_s3::config::Credentials::new(access_key.to_string(), secret_key.to_string(), None, None, "r2");
    let cfg = aws_config::from_env()
        .endpoint_url(endpoint_url)
        .credentials_provider(creds)
        .region("auto")
        .load().await;
    s3::Client::new(&cfg)
}
```

Note: newer `aws-config` may deprecate `from_env().endpoint_url` → use `aws_config::load_from_env()` + `aws_sdk_s3::config::Builder::from(&cfg).endpoint_url(...).credentials_provider(...).region(...).build()`. Test which compiles on current `aws-config 1.x`; support both.

### 3.4 Upload Logic

```rust
async fn upload(client: &s3::Client, bucket: &str, key: &str, file: &Path, content_type: Option<String>, verbose: bool) -> anyhow::Result<()> {
    let ct = content_type.or_else(|| mime_guess::from_path(file).first().map(|m| m.to_string()));
    let body = ByteStream::from_path(file).await
        .with_context(|| format!("failed to read {}", file.display()))?;
    let len = tokio::fs::metadata(file).await?.len(); // for logging
    if verbose { println!("Uploading {} ({} bytes) → s3://{}/{} as {}", file.display(), len, bucket, key, ct.as_deref().unwrap_or("application/octet-stream")); }
    let mut req = client.put_object().bucket(bucket).key(key).body(body);
    if let Some(ct) = ct { req = req.content_type(ct); }
    req.send().await.context("put_object failed")?;
    println!("Uploaded {} to s3://{}/{}", file.display(), bucket, key);
    Ok(())
}
```

*Streaming:* `ByteStream::from_path` avoids loading whole file into memory; SDK handles multipart automatically for large files. Explicit multipart tuning not needed v1.

*Error mapping:* Surface `SdkError` details via `anyhow::Context`; exit code 1 on failure, 0 on success.

### 3.5 `main` Wiring

```rust
#[tokio::main]
async fn main() -> anyhow::Result<()> {
    dotenvy::dotenv().ok();
    let cli = Cli::parse();
    match cli.command {
        Commands::Upload(args) => {
            if !args.file.is_file() { anyhow::bail!("not a file: {}", args.file.display()); }
            let client = build_client(args.account_id.as_deref(), args.endpoint.as_deref(), &args.access_key, &args.secret_key).await;
            let key = args.key.unwrap_or_else(|| args.file.file_name().unwrap().to_string_lossy().into());
            upload(&client, &args.bucket, &key, &args.file, args.content_type, cli.verbose).await?;
        }
    }
    Ok(())
}
```

### 3.6 Help & UX

- `clap` auto-generates `cloudflare-r2 --help` listing `upload` subcommand and `cloudflare-r2 upload --help` with env var hints (`[env: R2_BUCKET]`).
- Global `--verbose` works as `cloudflare_r2 --verbose upload ...` or `cloudflare_r2 upload ... --verbose` if `global=true`.
- On missing creds, clap error + custom hint: `R2_ACCESS_KEY_ID not set; pass --access-key or set env`.
- Future subcommands (`list`, `download`, `delete`) fit naturally under `Commands` enum.

## 5. Risks, Open Questions, Alternatives

**Risks:**
- `aws-sdk-s3` endpoint API drift: `aws_config::from_env().endpoint_url()` deprecated in favor of `aws_sdk_s3::config::Builder`. Mitigation: try new builder path; pin versions after `cargo tree`.
- `ByteStream::from_path` requires `tokio` file I/O; ensure `tokio` feature `fs` enabled via `full`.
- Large-file memory: safe via streaming, but SDK `put_object` still buffers; >5GB needs multipart. Document limit.
- Secret leakage: `--secret-key` on CLI leaks to shell history; warn to prefer env. `clap` `hide_env_values` prevents echo in help.

**Non-blocking open questions:**
- Progress bar? `indicatif` + `ByteStream` wrap. Deferred to v2.
- `.env` support: `dotenvy` cheap; recommendation include.
- Add `list`/`download` subcommands later? `Commands` enum already prepared.

**Rejected alternatives:**
- Flat CLI without subcommand (`cloudflare_r2 <FILE>`) — rejected per user request for `upload` subcommand.
- `reqwest` + manual AWS SigV4: more code, error prone.
- `s3` crate (`rust-s3`): not in Cloudflare docs.
- Config file (`~/.r2.toml`): user chose env/flag only.
