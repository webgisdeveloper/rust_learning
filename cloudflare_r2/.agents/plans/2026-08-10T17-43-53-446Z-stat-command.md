# Plan: Add `stat` Command (Single-Object Inspector)

## 1. Goal and Assumptions

**Goal:** Add `cloudflare_r2 stat <KEY>` (aliases `head`, `info`) to inspect one R2 object via `HeadObject` without downloading. Unblocks CI existence checks, content-type/metadata debugging, and fixes N+1 gap in `list --long`.

**Scope — Stat Alone (no copy/sync):**
- Single key lookup, human-readable default + `--json` machine output
- Reuses existing `endpoint_for` / `build_client` / error patterns
- No new dependencies
- No changes to `upload`/`download`/`list`/`delete` behavior

**Assumptions:**
- R2 `HeadObject` semantics = S3 (`is_not_found()` → 404). Keep identical error message to `delete`: `file not found: s3://{bucket}/{key}` (`src/r2.rs:87`)
- Region always `auto` (`src/r2.rs:251`), endpoint precedence `--endpoint` > `R2_ACCOUNT_ID` (`src/r2.rs:214-227`) unchanged
- Metadata keys remain `host` + `description` (`src/r2.rs:328-333`, `src/r2.rs:384-396`), but dump all `x-amz-meta-*` for completeness
- Output to stdout; verbose to stderr (existing convention `src/r2.rs:98`, `src/r2.rs:136`)

## 3. Proposed Implementation Steps

### Step 1 — CLI: `src/cli.rs`
1. Add `StatArgs` struct:
   ```rust
   #[derive(Args, Debug)]
   pub struct StatArgs {
       #[command(flatten)] pub r2: R2Args,
       #[arg(value_name="KEY")] pub key: String,
       #[arg(long)] pub json: bool, // --json for machine output
   }
   ```
2. Add to `Commands` enum:
   ```rust
   /// Show metadata for a single object (aliases: head, info)
   #[command(alias="head", alias="info")]
   Stat(StatArgs),
   ```
3. Add tests: `parses_stat`, `parses_stat_json`, `parses_stat_alias` + `rejects_empty_key` (handled in r2, but parse level).

**Files touched:** `src/cli.rs` only. No breaking flag changes.

### Step 2 — Core: `src/r2.rs`
1. **New struct** `StatInfo` (above `LongListItem:394`):
   ```rust
   struct StatInfo {
       key: String, bucket: String, size: i64, last_modified: Option<DateTime>,
       etag: Option<String>, content_type: Option<String>, content_encoding: Option<String>,
       storage_class: Option<String>, host: String, description: String,
       metadata: HashMap<String,String>, // all x-amz-meta-*
   }
   ```
2. **Helper** `async fn head_stat(client, bucket, key) -> Result<StatInfo>`:
   - Calls `client.head_object().bucket(bucket).key(key).send().await`
   - Match: `Ok(res)` → map fields; `Err(ServiceError(e)) if e.err().is_not_found() || e.err().is_no_such_key()` → `bail!("file not found: s3://{bucket}/{key}")`; other `Err` → `Context("head_object failed — check bucket, key, credentials, endpoint and network")` (mirror `r2.rs:88-92`, `r2.rs:168-171`)
   - Extract: `content_length()`, `last_modified()`, `e_tag()`, `content_type()`, `content_encoding()`, `storage_class()`, `metadata()`; default `host`/`description` to `"-"` if missing/empty (reuse `r2.rs:389-395` logic)
   - Return owned struct.

3. **Entry** `pub async fn run_stat(args: StatArgs, verbose: bool)`:
   - Validate `key = args.key.trim()`; `if key.is_empty() { bail!("object key must not be empty") }` (mirror `r2.rs:63`, `r2.rs:124`) + reject `key.ends_with('/')`? No — allow prefix-like keys; only reject empty.
   - `endpoint_for(&args.r2)?` + verbose `eprintln!("Endpoint: ...")` (mirror `r2.rs:127-133`)
   - `build_client(...).await` + `head_stat(...).await?`
   - Branch on `args.json`:
     - `true`: print single-line JSON via `serde_json::to_string` or manual `format!` (prefer `serde_json` dep to avoid escaping bugs)
     - `false`: print aligned human:
       ```
       Key:            {key}
       Bucket:         {bucket}
       Size:           {size} bytes
       Last-Modified:  {format_date or "-"}
       ETag:           {etag or "-"}
       Content-Type:   {ct or "-"}
       Host:           {host}
       Description:    {description}
       ```
       If `metadata` has extra keys beyond host/description, list under `Metadata:` section.
   - Verbose extra: `eprintln!("Stat s3://{bucket}/{key}")` (mirror `r2.rs:105`)

4. **Refactor (optional but recommended):** Refactor `fetch_object_metadata()` (`r2.rs:388`) to call `head_stat` internally and map to `(host, description)` to DRY. Keep backward compat or deprecate helper. Decision: implement `head_stat` first, then make `fetch_object_metadata` delegate (2-line change) — preserves `list --long` behavior while fixing duplication.

### Step 3 — Wiring: `src/main.rs:19-27`
Add arm:
```rust
Commands::Stat(args) => r2::run_stat(args, cli.verbose).await,
```

### Step 4 — Cargo.toml (conditional)
- If choosing `serde_json` for `--json`: add `serde = {version="1", features=["derive"]}` + `serde_json = "1"` (already transitively present via `aws-smithy-json:0.63` but not direct; adding explicit is clean). Alternative: avoid dep by manual JSON with `escape` — recommend adding dep (tiny).
- If no `--json` in v1, skip dep. **Recommended: include `--json`** as it's 5 LOC and unlocks scripting.

### Step 5 — Docs
- Update `README.md`: add `### Stat` section mirroring `### Delete` usage, env table unchanged, example:
  ```bash
  cloudflare_r2 stat test/README.md --bucket $R2_BUCKET --verbose
  cloudflare_r2 stat images/photo.jpg --json | jq .size
  cloudflare_r2 head images/photo.jpg --bucket $R2_BUCKET   # alias
  ```

**Manual integration (requires real R2 env):**
```bash

cargo run -- stat test/README.md --bucket $R2_BUCKET --verbose      # expect human output, exit 0
cargo run -- stat test/README.md --json | jq .                      # expect valid json, size>0
cargo run -- stat no/such/key --bucket $R2_BUCKET; echo $?         # expect "file not found: s3://..." exit 1
cargo run -- head test/README.md --bucket $R2_BUCKET                # alias works
cargo run -- list --bucket $R2_BUCKET --long --verbose              # regression: still works after refactor
```

**Error-path matrix:**
- Empty key → `bail!("object key must not be empty")` exit 1 (match `run_delete` validation)
- Wrong creds/endpoint → `head_object failed — check ...` with SDK cause, exit 1 (mirror `r2.rs:88`)
- No subcommand `stat` without KEY → clap error exit 2 (arg_required)

## 5. Risks, Open Questions, Rejected Alternatives

**Risks & Mitigations:**
| Risk | Likelihood | Mitigation |
|---|---|---|
| R2 returns `NoSuchKey` vs `NotFound` inconsistently (`r2.rs:86` vs `r2.rs:162`) | Medium | Match both `is_not_found()` **and** `is_no_such_key()` in head_stat error branch; add test comment linking both. |
| `list --long` regression if refactor `fetch_object_metadata` | Low | Keep `fetch_object_metadata` signature; make it delegate to `head_stat` but swallow extra fields; add `cargo test` guard for table format (`formats_long_table_aligned`). |
| Adding `serde_json` bumps compile time / binary size | Low | Conditional: `cargo add serde_json --optional` only if `--json` needed. Alt: manual JSON avoids dep but risks escaping bugs — prefer dep. |
| Output churn breaks scripts | Low | `--json` is stable contract; human output is not parsed — document in README. |

**Non-blocking Open Questions (no decision needed to start):**
- Should `--json` be `--format json` for future extensibility (e.g., `yaml`)? Recommend `--json` boolean for v1 (simpler), alias later to `--format`.
- Should `stat` support `--bucket` omission when `R2_BUCKET` env set? Yes — via `R2Args` flatten already handles `env="R2_BUCKET"` (`cli.rs:44`).
- Add `stat --long` to dump all headers? Defer — human default already shows all useful fields.

**Rejected Alternatives:**
| Alternative | Why Rejected |
|---|---|
| Make `list --prefix <exact-key>` serve as stat | Requires prefix scan + N heads; misleading semantics; can't distinguish missing vs empty prefix; breaks scripting. |
| Use `GetObject` + discard body | Wasteful bandwidth, slower, counts as GET not HEAD; fails for large objects; no benefit over `HeadObject`. |
| Extend `download --head` flag | Conflates concerns; download should remain streaming (`r2.rs:177` `tokio::io::copy`); stat is distinct verb. |
| Reuse `fetch_object_metadata` alone without `head_stat` struct | Loses `ETag`/`Content-Type`/`Size`/`Last-Modified` — would require second head call later; struct centralizes mapping. |
| Skip `--json` for v1 | Saves dep but loses scripting value; users would parse human output brittlely; cost is minimal. |
